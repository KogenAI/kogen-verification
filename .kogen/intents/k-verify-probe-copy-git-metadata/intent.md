# Carry source git metadata into probe copies

Slug: k-verify-probe-copy-git-metadata
Model: not applicable — each probe builds its copy's repository once and deletes it with the scratch copy; there is no state or lifecycle beyond the existing probe run
Acceptance:
- .kogen/intents/k-verify-probe-copy-git-metadata/acceptance.feature
- features/steps/k-verify-probe-copy-git-metadata__steps.js

A probe's scratch copy (verify.Probe.Run, used by readiness for every declared feasibility check and by other disposable probes) gets git metadata, so that read-only git commands in a probe see the same history the source checkout has at its HEAD. Today the copy has no `.git`, so an observer that runs `git show <commit>:<path>`, `git rev-parse HEAD` or `git grep` at HEAD fails with `fatal: not a git repository` for its good and bad control alike, and readiness refuses the Intent as "declared feasibility evidence failed" although the observer is correct. This replaces the "no git metadata" behaviour of `k-verify-probe-no-git` for sources that are git checkouts; for sources that are not, it stays exactly as today.

Current behaviour (verify/probe.go): `CopyTree` copies the working tree without `.git` and `.kogen/local`; `Probe.Run` runs the command in that copy and, when the combined output contains `fatal: not a git repository`, appends the line `probe copy has no git metadata: scratch-copy isolation, not evidence that the source project lacks a repository` (after adding a newline if the output lacks a final one).

Required behaviour, in `Probe.Run` (the exported `CopyTree` keeps its signature and behaviour):

1. Right after `CopyTree` and before the probe's `Files` are laid over the copy, `Probe.Run` gives the copy a repository of its own at `<scratch>/.git` when the source root is the top level of a git work tree (a main checkout or a linked worktree, whose `.git` is a file) and the source's HEAD resolves to an existing commit (`git rev-parse --verify --quiet HEAD^{commit}` succeeds in the source). The copy's repository:
   - is a fresh non-bare repository with the source's object format, created without a template, so it has no sample or other hooks;
   - borrows the source's object database read-only: the source's objects directory as git resolves it in the source (`git rev-parse --path-format=absolute --git-path objects`, which is the common directory's objects for a linked worktree) is listed in the copy's `objects/info/alternates`; the source's `shallow` file, when the source has one, is copied into the copy so a shallow history stays readable;
   - has HEAD as the source has it: when the source's HEAD is the branch `refs/heads/<name>`, the copy has that branch at the source's HEAD commit and HEAD is a symbolic ref to it, so `git rev-parse --abbrev-ref HEAD` prints `<name>` and `git log` shows the branch history; when the source's HEAD is detached, the copy's HEAD is detached at the same commit;
   - has an index read from HEAD (`git read-tree HEAD`), while the copied working tree, including uncommitted, untracked and the probe's own files, is left exactly as copied; so `git status` shows the source's uncommitted and untracked files as changes, and changes staged only in the source's index appear as unstaged or untracked, not staged;
   - has hooks disabled: its local config sets `core.hooksPath` to a location holding no hooks (for example `/dev/null`), so no hook runs in the copy, including hooks present in the source;
   - carries nothing from the source's local config: no identity, no remotes, no other keys; it has no remote at all, and no refs besides the one branch (or detached HEAD) above.
   The setup git commands run with the probe's own environment (the one `probeEnv` builds, with the probe's private HOME), only read the source (for example `rev-parse`, `symbolic-ref`), and take no optional locks (`GIT_OPTIONAL_LOCKS=0`), so the source's status, local config, HEAD, refs, objects, index, hooks directory and files stay byte-identical. The setup runs before the probe's wall time starts, like the copy itself.
2. When the source is not such a checkout (no repository, not the work tree's top level, a repository with no commit, HEAD naming a missing commit), or git is unavailable, or any setup step fails, the copy has no `.git` (a partly created one is removed) and the probe runs exactly as today: no error is returned and no extra output is added because of the setup.
3. The existing explanation logic is unchanged: `Probe.Run` still appends the explanation line whenever the combined output contains `fatal: not a git repository`, whether or not the copy has a repository, so a non-checkout source keeps today's output exactly and a probe that never calls git keeps its exact output even when it prints that text.
4. Nothing a probe does to git or files in its copy (config changes, commits, new branches, new files, commits while the source has hooks) reaches the source checkout. The copy, its repository and the borrowed-object link are deleted with the scratch copy as today.
5. Probes that never call git keep their exit status and output exactly. The only difference such a probe can see is the copy's top-level `.git` entry, the repository this Intent adds.

Out of scope: no change to `probeEnv`, `CopyTree`, timeouts, process cleanup, input-change accounting, feasibility declaration rules or readiness records; no new settings. The `k-verify-probe-no-git` Intent files stay untouched as a historical record; its scenarios use a repository with no commit, which still gets today's behaviour under rule 2.

Tests: in verify/probe_git_test.go, `TestProbeGitMetadataIsolation` (which pins a probe's `git status` failing with status 128 and the explanation) is replaced by tests for the new contract below, keeping its isolation assertions (the source's `probe.sentinel` config stays `original`, no `scratch-only` file appears in the source) for a probe that changes git config, commits and writes files. `TestProbeGitDiagnosticWithoutFinalNewline` (a non-git source) stays.

## Decisions
- The copy's repository is created in Probe.Run after CopyTree, with the source's objects borrowed read-only through alternates, HEAD and the current branch (or detached HEAD) at the source's commit, an index read from HEAD, hooks disabled and no local config or remotes from the source (source: request).
- A source that is not a git work tree top level, has no commit, or whose HEAD names a missing commit, and any failure while creating the copy's repository, leave the copy without `.git` and the probe as today, including the explanation (source: request).
- The explanation is appended exactly as today, so probes that never call git keep their exact output (source: request).
- The contract test pinning the old behaviour is replaced; its isolation assertions stay (source: request).

## Tests
- A probe of a committed source reads `git show HEAD:<path>`, `git show <older commit>:<path>`, `git rev-parse HEAD`, `git rev-parse --abbrev-ref HEAD`, `git log` and `git grep … HEAD` as in the source: new test in verify/probe_git_test.go replacing TestProbeGitMetadataIsolation (integration)
- Uncommitted and untracked source files show as changes in the copy, and the copy's index matches HEAD rather than the source's index: same file, `git status --short` in the probe (integration)
- Config changes, commits, branches and files made by a probe, with a post-commit hook in the source, leave the source's status, local config (`probe.sentinel` still `original`), HEAD, objects, hooks directory and files unchanged and no `scratch-only` or hook marker in the source: same file, keeping the replaced test's isolation assertions (integration)
- The source's local config (identity, remotes, other keys) is not in the copy and the copy has no remote: same file (integration)
- A detached source HEAD gives a copy detached at the same commit; a linked worktree source, a shallow clone source and a SHA-256 source give readable HEAD and history in the copy: same file (integration)
- A non-checkout source, a repository with no commit and a HEAD naming a missing commit leave the copy without `.git`; `git status` fails with the existing explanation and other commands run as today without an error: same file (regression)
- A non-git source keeps the explanation after output without a final newline: TestProbeGitDiagnosticWithoutFinalNewline (existing)
- Probes that never call git keep their exact status and output: existing probe tests in package verify, and the acceptance ten-command scenario (existing)
- End to end through Probe.Run and verify.Execute, the request's synthetic acceptance 1–6 plus the index, local config, worktree and fallback cases: .kogen/intents/k-verify-probe-copy-git-metadata/acceptance.feature (scenario)
