# Record reproducible check run identities

Slug: k-verify-check-run-identity
Model: not applicable — this adds a deterministic snapshot and hashing transformation to existing passes, not a new state machine
Acceptance:
- .kogen/intents/k-verify-check-run-identity/acceptance.feature
- features/steps/k-verify-check-run-identity__steps.js

Add identity evidence to verification logs without changing Pass JSON, command results, scheduling, cleanup, readiness decisions or reuse policy. This implements REQUEST k-verify-check-run-identity (kogen-verification), general mechanism: command text alone currently cannot establish whether checks used the same candidate, dependencies, tools, environment and host class. This change records that evidence; it does not itself decide whether a red was flaky or reuse old evidence.

## Decisions
- Emit exactly one `check_identity` before the first pass item, after materializing the candidate, including empty passes. Snapshot once before setup; never rerun version probes for individual items. Apply to ordinary and stage Verify passes, serial and concurrent commands, acceptance and model command events within the pass. Fix runs before materialization and is outside this pass identity; standalone probes/readiness commands outside Verify are unchanged. (evidence: verify/run.go; verify/concurrent.go) (source: request)
- Hash the effective session environment after configured Tools overrides, with duplicate variable names resolved exactly as execution resolves them. Do not use the shaper/builder parent environment when it is not passed to checks. Exclude only Kogen-generated per-execution cleanup marker values and temporary report locations (`KOGEN_STEP_RUN`, `KOGEN_ACCEPTANCE_RUN`, `KOGEN_CHECK_REPORT`, `KOGEN_ACCEPTANCE_REPORT`); these are execution transport, not reproducible check inputs. Do not remove ordinary caller variables, PATH or configured KOGEN_NODE/KOGEN_QUINT/KOGEN_CUCUMBER. Keep runtime marker/report behavior unchanged. (evidence: verify/env.go; verify/sweep.go; verify/run.go; verify/concurrent.go) (source: request)
- The exclusion above resolves the conflict between literal process-environment hashing and identical-pass identities: fresh random markers and temporary report paths must not destroy synthetic acceptance 1. The stable effective pass environment is the record's scope, not transient command-specific execution plumbing or shell-generated PWD/SHLVL. (assumption: the request's reproducibility guarantee takes precedence over including generated transport values) (source: request)
- Record the exact materialized candidate Git tree digest already exposed as Pass.Tree; do not hash checkout HEAD or scratch directory names. Lockfiles mean root-relative paths from the fixed list, not recursive discovery. (evidence: verify/run.go) (source: request)
- Use a one-second timeout per version command, bound captured output to 4096 bytes and retained first line to 512 bytes. Preserve resolved executable paths (up to 4096 bytes). Absence, timeout and unsuccessful version execution are evidence, never pass failures. Kill version processes on timeout, including descendants, without emitting raw captured diagnostics. (assumption: one second is the requested short timeout and these limits retain useful bounded evidence) (source: request)

The log schema is additive. A `check_identity` has exactly `event`, `tree`, `tools`, `lockfiles`, `environment`, `host` (the Logger may add its existing timestamp). `tools` is an array in this exact order: go, node, npm, ruby, bundle, python3, elixir, erl, mix, git, quint. Each entry has `name`, `path` (resolved absolute executable path or null when absent), `status` (`ok`, `absent`, `timed_out`, or `error`), and `version` (first output line, null when not ok). Resolve against the effective check PATH, not the host process PATH. Run go with `version`; node, npm, ruby, bundle, python3, elixir, mix, git and quint with `--version`; erl with `-noshell -eval 'io:format("~s~n", [erlang:system_info(otp_release)]), halt().'`. Use combined stdout/stderr and the first nonempty line, dropping its line terminator; ignore later lines. Probe each resolved executable exactly once per pass.

`lockfiles` contains only present files, in this order: go.sum, go.mod, mix.lock, package-lock.json, yarn.lock, pnpm-lock.yaml, Gemfile.lock, poetry.lock, requirements.txt. Each entry is `{path, sha256}` hashing exact materialized bytes with lowercase SHA-256 hex. No unrelated files or tools are listed. `environment` is `{names, sha256}`: names are unique and lexicographically sorted; sha256 is the hash of compact UTF-8 JSON of sorted `[name,value]` pairs of the stable effective environment defined above. No values or plaintext pairs are ever emitted. `host` is `{os,arch}` using Go runtime.GOOS/runtime.GOARCH, never hostname.

Every pass `command` event gains lowercase hex `identity_sha256`, SHA-256 of compact UTF-8 JSON of `[command, tree, tools, lockfiles, environment, host]`. Canonicalize every object's keys lexicographically, recursively; retain array order, use JSON strings without HTML escaping, and no insignificant whitespace or trailing newline. The `event` field and timestamps are not hash inputs. Tool paths, statuses and version lines are hash inputs, as are environment names/digest and lockfile paths/digests. Preserve the original exact command text. Identical inputs yield identical hashes; changing any material input changes the hash. Never log environment values during collection or failure handling; the synthetic check commands do not print their secret. Existing command output logging is not a new secret-redaction feature.
