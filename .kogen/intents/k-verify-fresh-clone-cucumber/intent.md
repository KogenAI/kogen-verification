# Prepare Cucumber for tests in a fresh clone

Slug: k-verify-fresh-clone-cucumber
Model: not applicable — the change adds a setup program, a shared lookup that fails a test with one message, and README text; there is no state or interacting rules to model
Acceptance:
- .kogen/intents/k-verify-fresh-clone-cucumber/acceptance.feature
- features/steps/k-verify-fresh-clone-cucumber__steps.js

A fresh clone of kogen-verification fails `go test ./...` until Cucumber is installed by hand, and the failures do not say that Cucumber is the missing prerequisite. kogen-shaping consumes this module and has the same problem. After this change one named setup command installs what the tests need, every test that needs Cucumber and cannot find it fails with one message that names the prerequisite and that command, and a consumer module reuses the same lookup and the same command without copying them.

The setup command is `go run github.com/KogenAI/kogen-verification/cmd/setup-tools`. Run in a module root it makes sure `testdata/tools/cucumber` and `testdata/tools/quint` each hold the pinned `package.json` and `package-lock.json` (writing this module's copy of a file only when it is absent), then runs `npm ci --prefix testdata/tools/cucumber` and `npm ci --prefix testdata/tools/quint`, in that order, with npm's output passed through. When an `npm ci` fails, the program stops without running the next one, prints `setup-tools: npm ci --prefix <folder> failed: <error>` to standard error and exits with status 1. The pinned versions stay in the existing `testdata/tools` files; no second committed copy is made (the program embeds them from there).

The shared lookup is the exported function `prereq.Cucumber(t testing.TB) string` in the new package `github.com/KogenAI/kogen-verification/prereq`. It returns the `node_modules` folder that holds `@cucumber/cucumber/bin/cucumber.js`: the folder named by the environment variable `KOGEN_CUCUMBER` when it holds that file, otherwise `testdata/tools/cucumber/node_modules` under the nearest folder at or above the working directory that holds a `go.mod`. When neither holds it, the test fails (`t.Fatal`) with exactly this one message, which the package also exports as the constant `prereq.CucumberMissing`, built from the exported constant `prereq.SetupCommand`:

`missing prerequisite: Cucumber is not installed; run the setup command: go run github.com/KogenAI/kogen-verification/cmd/setup-tools`

Every test in `verify` that needs Cucumber calls `prereq.Cucumber` first, before looking for Node or Quint: `realTools` in `verify/helper_test.go` (which today skips when Cucumber is missing) and `warnProject` in `verify/unused_step_warn_test.go` (which today fails with its own text). Their ad hoc "run npm ci" texts are removed. A missing Quint stays a skip, now naming the setup command. A test that does not need Cucumber is not affected by a missing Cucumber.

The README's Testing section gets a `### Prerequisites` subsection that lists Go, Node.js with npm and the setup command, in one fenced block, and the two separate `npm ci --prefix` instructions are removed from it: the command appears once in the README. The README says that consumers use `prereq.Cucumber(t)` and the same command in their own module root.

Out of scope and unchanged: `.kogen/` (including `.kogen/project.yaml` and its setup commands), the tests' behavior once Cucumber is found, installed-Kogen handling (earlier fix 25884c5), and any automatic download from a test or a step.

## Decisions
- The one named setup command is a Go program, `go run github.com/KogenAI/kogen-verification/cmd/setup-tools`, because the same single command must work in this clone and in a consumer module, and Go and Node are the only prerequisites. It installs Cucumber and Quint, as the README's two commands do today.
