## Decisions
- Cheap prerequisite gates stay non-speculative. Independent expensive gates may overlap only after preceding prerequisites pass. Failure cancels unnecessary work; started/cancelled work is distinct from never-started work. (source: request)
- Configured file handoffs continue working. Only established independence allows concurrency; unknown/custom commands retain serial behaviour. (source: request)
- The first failure in declaration order determines the stop. Earlier checks finish even when a later check already failed. Completed later evidence is retained separately; running later work is cancelled once the ordered stop is known. (source: request)
- Repair feedback requests repair of the stopping failure only. Use separate headings `Speculative results` and `Cancelled work` for later evidence and cancellations. (source: request)

### Technical settlement

Keep declaration order, not completion order, authoritative. Establish independence for adjacent configured checks whose entire command is exactly `go build ./...` or `go vet ./...`, including trimpath-only spellings `GOFLAGS=-trimpath go build ./...` and `GOFLAGS=-trimpath go vet ./...`. Standard build and vet compile/analyse the sources without running repository tests; vet does not consume build's resulting executable, if any. Preserve build's existing artifact/mutation semantics: a single-main-package `go build ./...` can write an executable. Recognise commands, never names alone. A custom command named compile, vet, test, spec, cucumber or full-acceptance does not become independent by its name. Arbitrary `go test`, npm scripts, Cucumber steps and acceptance commands may have side effects. Every other command is a barrier: finish the preceding cohort before starting it, and do not speculate past it. Do not guess dependencies by parsing arbitrary shell commands, add opt-ins, rewrite caller commands, or execute them twice. Preserve caller environment and command bytes; nonstandard Go execution overrides such as GOFLAGS=-toolexec invalidate standard-command independence and must stay serial. PATH resolution itself remains normal command execution (the acceptance shim uses it). The Go cache's documented concurrency safety does not establish independence of arbitrary tests.

For green cohorts, retain ordered CommandResult Name, Command, Status and Output in Pass.Checks unchanged. On failure, Checks contains the authoritative prefix through the stopping failure; Failing contains that stopping failure only, while existing integrity/mutation evidence remains effective. Add exported `Speculative []CommandResult` and `Cancelled []CommandResult` to Pass with JSON `speculative` and `cancelled`, omitted when empty. Speculative contains completed later results, successful or failed, in declaration order. Cancelled contains started later commands that required cancellation, in declaration order, with original command and partial output; status -1 means cancellation, not an ordinary failure. NotRun contains only never-started items. Every started check belongs to exactly one of these three result lists. Never discard later success. Complete/reuse rejects speculative/cancelled evidence as whole green proof. Old valid serial/legacy green records remain reusable; missing new fields mean empty. Preserve per-command logging and output, classify speculative/cancelled evidence unambiguously. Diagnostic command_result events may reflect actual completion times; rendered pass results retain declaration order. Feedback/summaries must not mislabel cancelled work as never run or turn later failures into repair requests.

Remove shared-session snapshot inference for concurrently watched commands. The previous 03 Nov 14:46Z attempt, Build 16e1e4b4, stopped review_blocked: verify/hung.go:61-65 chose the first process group absent from a shared pre-start snapshot, allowing overlapping watchers to choose the same group and hang/kill the wrong check. Give each concurrent check exclusive execution custody before launch: a dedicated child sys.Session, one command, its own cancellation context. Its groups come solely from that command's registration, never shared before/after inference. Watch/kill only that owned execution. Propagate parent context/caller interruption and join cancellation/sweeps before deleting scratch state, including cancellation during startup. Preserve orphan sweeping, foreign-kill policy, no-live-process detection, timeout/interrupt classifications, output caps, checkout/scratch mutation checks, logs and evidence. Synchronize shared writers/evidence/logging to avoid races. Never raise noLiveGrace, StepTimeout, sweep grace or another limit/deadline. End once the ordered answer and necessary cleanup are complete rather than waiting for unnecessary expensive work. Never cancel an earlier check for a later failure.

The protected driver overlays its submitted test into an independent copy, reuses newProj's real seeded synthetic Cucumber messages and calls Verify. Its Go PATH shim uses bounded rendezvous, exact outputs/statuses, and command_result evidence to distinguish completion from mere process launch. It covers overlap, cheap stop, reverse-order failures, completed speculation, cancellation of a check with a child while a caller-session bystander survives, and custom file handoffs. This is not a named test the builder must invent. Add focused implementation coverage for successful speculative results, watcher live/hung isolation, start-boundary cancellation, caller interruption, round-trip records and Complete/reuse. Use local processes and observable synchronization, not sleep durations as ordering assertions.
