# Trust tool configuration in a probe's own TMPDIR

Slug: k-probe-mise-second-tmp
Model: not applicable — one private directory and two environment values added to each probe run; no state or interacting rules
Acceptance:
- .kogen/intents/k-probe-mise-second-tmp/acceptance.feature
- features/steps/probe_second_tmp_steps.js
- features/steps/probe_trust_steps.js
- features/steps/probetrust.go

A probe (`verify.Probe.Run`, SHP-10) runs its command in a scratch copy `<os.TempDir()>/kogen-probe-<hex>` with an allowlisted environment and a private HOME. Since k-shape-probe-mise-trust it sets `MISE_TRUSTED_CONFIG_PATHS=<scratch>[:<caller value>]`, so mise trusts the project's tool configuration in the scratch copy. A control that makes a second temporary directory of its own, copies the project (or its tool configuration) there and runs the project's tool there still fails. The probe passes no TMPDIR now, so that directory lands in the system default (`/tmp/...`), outside every trusted path, and mise refuses it: "Config files in /private/tmp/billing.XXXXXX/p/.mise.toml are not trusted."

After this change each probe run gets a private temporary directory of its own. `Probe.Run` creates it with `os.MkdirTemp("", "kogen-probe-tmp-")`, a new empty directory in the caller's temporary folder that is neither inside the scratch copy nor the probe's HOME. It is created before the command starts and removed with `os.RemoveAll` on every return: success, a refused probe, an error and an interrupt, the same as the private HOME. The probe's environment gains `TMPDIR=<that directory>`, and `MISE_TRUSTED_CONFIG_PATHS` becomes `<scratch>:<that directory>`, followed by `:` and the caller session's value only when that value is nonempty. Temporary directories the run creates through TMPDIR (`mktemp -d "$TMPDIR/name.XXXXXX"`, Node `os.tmpdir()`, Python `tempfile`, Ruby `Dir.mktmpdir`, Go `os.MkdirTemp("", …)`) therefore lie inside a trusted directory that holds only what the run itself put there.

Nothing else changes. The probe still ignores the caller's own TMPDIR, as before: it was never allowlisted, and the probe's private directory now takes its place. PATH and the other allowlisted variables (`probeEnvKeys`), the private HOME, HEX_HOME and MIX_HOME stay as they are. The probe trusts no other location. That excludes the caller's temporary folder itself, sibling directories in it, `/tmp`, `/` and any configuration outside the scratch copy and the run's own temporary directory that the caller does not already trust. A control that genuinely fails still fails with its own status and combined output, and the `verify.Execute` refusal (`intent/not_ready` "declared feasibility evidence failed" with `<id>/<check>: expected {...}; actual {...}` lines) stays as it is. No CLI command, flag or setting is added.

Boundary: a directory the run creates outside its TMPDIR is not trusted, because trusting it would trust configuration from outside the project. Examples are a fixed `/tmp/...` path and macOS `/usr/bin/mktemp -d` or `mktemp -t` without a template, which use the per-user `_CS_DARWIN_USER_TEMP_DIR` (`/var/folders/.../T/`) and ignore TMPDIR. This was observed on the shaping host (macOS 26, mise 2026.10.15).

The acceptance harness `features/steps/probetrust.go` is a `main` package that the steps build with `go build ./features/steps`. It calls `verify.Probe{Root, Command}.Run` and `verify.Execute` and uses its own process environment as the caller's, including the caller's TMPDIR, which the steps set to a fresh directory so they can observe what the probe creates and leaves there. The Build keeps `verify.Probe`, `ProbeResult`, `verify.Execute` and `verify.Tools` usable the way that harness uses them.

## Decisions
- A probe's own run trusts the project's tool configuration wherever that configuration is legitimately used during the run: in the scratch copy and in temporary directories the run creates. (source: request)
- The probe trusts no configuration from outside the project. Its run's temporary directories go in a private directory that only the run writes to, and only that directory is trusted. The caller's temporary folder, `/tmp` and `/` are not trusted. (source: request)
- The probe's isolation from the user's real home and scratch state (SHP-10) stays: the private HOME and the allowlisted environment are unchanged, and the run's temporary directory is private and removed afterwards. (source: request)
- No new CLI commands or flags. (source: request)

## Source comparison
- Problem ("the billing-driver control creates its own second temporary directory, and mise still refuses that directory's configuration as untrusted"): addressed by `TMPDIR=<private run directory>` and by adding that directory to `MISE_TRUSTED_CONFIG_PATHS` in `Probe.Run`. The synthetic fixture control `bin/second-tmp` creates `mktemp -d "${TMPDIR:-/tmp}/second-tmp.XXXXXX"`, copies the project there and runs the fake mise shim `greet` there. Scenarios: "A control that runs the project's tool in a temporary directory it creates passes as a probe", "A control that genuinely fails in a temporary directory it creates still fails as a probe" and "A declared observer whose good control runs in a temporary directory it creates is met". On the unchanged tree these fail with `greet: Config files in /tmp/second-tmp.XXXXXX/project/.mise.toml are not trusted.`
- Need "including temporary directories the run creates": TMPDIR-based creation is covered. The boundary (a fixed `/tmp` path or macOS bare `mktemp -d` / `mktemp -t`, which ignore TMPDIR) is stated above and not trusted, because the Need forbids trusting configuration from outside the project. The billing driver's exact creation call is not in this repository, and the cited notes (`~/Scratch.noindex/kogen-lanes-private/notes-harness/climb/verification/LANE.md`, `l1probe/results/`) were not readable from this shaping session. If the replay's driver uses one of those non-TMPDIR forms, it remains outside this contract.
- Need "without trusting configuration from outside the project": scenarios "A probe trusts no tool configuration in the caller's temporary directory", which tells this design apart from trusting `os.TempDir()`, and "A probe trusts no tool configuration outside its copy of the project", which keeps the k-shape-probe-mise-trust guard against trusting `/`.
- Disposable probe (SHP-10), kept from k-shape-probe-mise-trust: the scenario "The control's temporary directory is inside the probe's own temporary directory, which the probe removes" checks that the control's directory was `<caller tmp>/kogen-probe-tmp-<random>/second-tmp.<random>` and that no `kogen-probe*` entry is left in the caller's temporary folder.
- Measured host evidence (eu2 replay: candidate 2/6, previous release 0/6, `MISE_TRUSTED_CONFIG_PATHS=/` 6/6): historical, not re-measured here. On this shaping host (mise 2026.10.15, macOS), a session-shell check outside the repository ran the harness built from the unchanged tree. It showed real mise refusing `/private/tmp/billing.XXXXXX/p/.mise.toml` inside a probe. A scratch candidate with this design made real mise accept the TMPDIR-created copy, with the caller's TMPDIR both a plain directory and `/tmp`, and also a Python `tempfile.mkdtemp()` copy. It still refused a `.mise.toml` in a sibling directory of the caller's temporary folder. This is not a Kogen probe record.
- Constraints "Synthetic tests only (a fixture control that creates a second temp dir); no model runs; no new CLI commands or flags": the acceptance and the Go regression test use a generated project, a fake `greet` shim and a generated shell control. They make no model run and use no real mise, and add no command or flag.
- "Research re-screens with the same replay on eu2": a post-landing research activity, outside this Build.

## Tests
- A probe's environment sets TMPDIR to its private run directory and `MISE_TRUSTED_CONFIG_PATHS` to `<scratch>:<run directory>`, followed by `:` and the caller's value when nonempty, and otherwise keeps the allowlisted environment and private HOME: update `TestShapeProbeMinimalEnvironment` in `verify/evidence_test.go`. It asserts that TMPDIR is `<tmp>/kogen-probe-tmp-*`, exists and is empty during the run, and is neither the scratch copy, inside it, nor HOME. It asserts the trust value for a caller without the variable, with an empty one and with one, and that a caller TMPDIR is not passed on (integration)
- A control that creates a second temporary directory under TMPDIR, copies the project there and runs a shim that trusts configuration only under `MISE_TRUSTED_CONFIG_PATHS` exits 0 as a probe, and its declared check is met by `Execute`. A copy in a sibling directory of the caller's temporary folder stays untrusted: extend `TestProbeTrustsTheProjectToolConfigurationOfItsScratchCopy` in `verify/evidence_test.go`, failing on the unfixed probe with the "not trusted" output (regression)
- The run's private temporary directory is removed on every return, refusal and interrupt included: `TestShapeProbeMinimalEnvironmentHomeIsRemovedOnEveryReturn` and the other `requireNoLeftovers` checks, whose `kogen-probe` prefix covers `kogen-probe-tmp-` (existing)
- End to end through `verify.Probe.Run` and `verify.Execute`, the second-temporary-directory control passes, its genuine failure keeps its own status and output, its directory lies in the probe's own removed temporary directory, and configuration in the caller's temporary folder or elsewhere stays untrusted: the acceptance scenarios through `features/steps/probetrust.go` (scenario)
- Trust of the scratch copy and the probe's SHP-10 isolation are unchanged: the k-shape-probe-mise-trust scenarios and `TestShapeProbeMixAndHexHomes` (existing)
