Bind every verification command's launch and running lifetime to its caller's context. A canceled caller must not get success from a command that continued running: stop and join that command's owned processes before returning cancellation. Cancellation already observed before launch prevents launch; cancellation across the launch/registration handoff must not escape custody. Apply to disposable probes, ordinary verification commands and approval-attempt commands. Keep unrelated commands alive. Preserve uncancelled status and output, session-interrupt precedence, existing timeout limits/classification and owned-descendant cleanup. Do not add settings, broaden process ownership or change unrelated command execution.

## Decisions
- Cancellation stops the owned command before returning; prelaunch cancellation prevents launch, including the cancellation/start race. No new UI or configuration is introduced. (source: request)
- Exercise the readiness-marker, brief sleep, delayed second-marker reproducer through probes, ordinary verification steps and approval steps, beside an independently owned bystander. Preserve original results, real timeout feedback and session interrupt results. (source: request)

Technical settlement: the pinned `kogen-loop` already has `Session.RunContext(ctx, command, dir, Options)`. Its installed source documents and implements launch locking, context checks at start, whole-group termination and joining; `Session.Run` calls it with nil context. `Options.Context` alone is timeout-custody cancellation, not running-command cancellation. Use the context-bearing runner at the actual launches in `verify/probe.go`, `verify/env.go` and `verify/attempt.go`. Preserve the probe injection seam: its default adapter can call `s.RunContext(o.Context, command, dir, o)` without changing the existing `ContractProbeRun` signature. Keep `Options.Context` where timeout custody already uses it. Preserve probe isolation, foreign-kill refusal, tool environments, per-step sweeping/reaper behavior, attempt recording and ordinary no-progress watching. Return the observed session interrupt rather than generic context cancellation when both are observed. Do not implement cancellation by interrupting the shared caller session or killing all of its groups.

Acceptance installs the submitted Go driver as a test file only in an isolated copy and compiles a test binary. It calls `Probe.Run` and the real shared verification-step boundary `runStep`, both without and with `NewAttempt(...).Into(ctx)`. These are the launch paths used by verification and approval, rather than a fake runner. No production files are acceptance inputs. The report is invocation-nonce-bound JSON, not a test-runner summary or an unwritten builder test. The driver uses the existing pinned dependency's test-only `startHook` through a test-binary-only linkname: `enter` is before launch checking, `starting` is after process creation before registration under the session lock, and `started` is after registration. No module-cache edits or new production test hooks are needed. Those handoffs test both cancellation-before-start and cancellation-after-start orderings deterministically. Background children and a sleep grandchild are checked at return, before cleanup; the second marker is checked again after its scheduled write time. A zombie is not a surviving live process. All fixture waits have bounds.

Timeout fixtures contract the existing probe/approval bounds to 150 ms, then check timeout rather than cancellation and that the delayed write did not occur. Production limits remain ProbeTimeout=5 minutes and StepTimeout=120 seconds. Ordinary verification gains no new timeout. Session-interrupt-before cases also have a canceled caller, explicitly exercising precedence; running-interrupt cases preserve the running interrupt result. Existing interrupt tests retain SIGTERM/SIGHUP coverage. Controls run the same fixture against the installed dependency's context-bearing runner (good) and non-context runner (bad); they qualify the protected fixture/observer, not the unimplemented product. Each good observation is also independently corrupted per asserted field to ensure deeper predicates are not masked by earlier red.
